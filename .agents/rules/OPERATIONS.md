أنت وكيل تطوير وتشغيل مسؤول عن مشروع "صفقات ذكية" داخل Antigravity.

يجب عليك تطبيق قاعدة تشغيل إلزامية على كل تعديل في المشروع:

بعد كل تعديل فعلي على ملفات الكود أو الإعدادات أو الاعتماديات، يجب عليك:
1. اكتشاف أمر تشغيل المنصة الصحيح.
2. التحقق من أن إعدادات Run/Preview/Launch تشير إلى الأمر الصحيح.
3. تحديث ملف إعداد التشغيل إذا كان ناقصًا أو قديمًا.
4. تشغيل فحوصات المشروع.
5. تشغيل المنصة أو إعادة تشغيلها.
6. التحقق من أنها تستجيب بنجاح.
7. فتح أو تحديث Browser Preview عند توفره.
8. تسجيل النتيجة بوضوح في تقرير.
9. عدم اعتبار المهمة مكتملة إذا لم ينجح التشغيل أو بقيت أخطاء غير معالجة.

==================================================
## تعريف "تعديل مؤثر"
==================================================

اعتبر التغيير مؤثرًا إذا شمل أيًا من:
- ملفات Python, Django, JavaScript, TypeScript.
- React/Vue/HTML/CSS.
- settings أو environment configuration.
- requirements.txt أو pyproject.toml أو package.json.
- Dockerfile أو docker-compose.
- urls أو routes أو models أو migrations.
- APIs, authentication, permissions, upload/download handlers.
- Celery, Redis, إعدادات static/media.
- ملفات Run/Debug/Launch وملفات build.

لا يلزم إعادة تشغيل المنصة بعد تعديل: README، تعليقات، مستندات، ملفات تصميم.
إذا لم تكن متأكدًا، اعتبر التعديل مؤثرًا ونفذ دورة التحقق كاملة.

==================================================
## المرحلة الأولى: اكتشاف بيئة التشغيل
==================================================

استخرج أوامر التشغيل الفعلية فقط بعد فحص الملفات (Django, Node, Docker, etc).
أعطِ الأولوية بهذا الترتيب:
- Django فقط: `python manage.py runserver`
- Django + Frontend: `python manage.py runserver` و `npm run dev`

==================================================
## المرحلة الثانية: توحيد زر التشغيل
==================================================

أنشئ أو حدّث إعداد تشغيل مركزي واضح (مثل `تشغيل_المنصة.bat` أو scripts في package.json أو vscode/launch.json).
لا تنشئ إعدادات متعارضة مع إعدادات الفريق.

==================================================
## المرحلة الثالثة: دورة ما بعد كل تعديل
==================================================

### A. فحص التغييرات (git diff)
### B. فحوصات Django (`python manage.py check`, `makemigrations --check --dry-run`)
### C. فحوصات Frontend (lint, typecheck, test)
### D. الاختبارات (`python manage.py test`)
### E. تشغيل المنصة (إعادة تشغيل إن لزم الأمر)
### F. فحص الصحة (تأكد أن المنفذ يستمع ولا توجد أخطاء)
### G. Browser Preview (عبر `/browser` أو الفحص المحلي)

==================================================
## تقرير ما بعد التعديل
==================================================

بعد كل تعديل مؤثر، أخرج تقريرًا بهذه الصيغة:

### التعديل
- وصف مختصر.
### الملفات المتغيرة
- قائمة الملفات.
### أمر التشغيل المعتمد
```bash
[command]
```
### إعداد زر التشغيل
- الملف الذي تم تحديثه، الأمر المرتبط، حالة التحديث.
### الفحوصات
- Django check: PASS/FAIL
- Migration check: PASS/FAIL
- Lint/Tests/Build: PASS/FAIL/SKIPPED
### التشغيل
- الخادم: RUNNING/FAILED
- الرابط المحلي:
- Health check: PASS/FAIL
- Browser Preview: PASS/FAIL/SKIPPED
### الأخطاء المتبقية
- اذكرها بوضوح.
### القرار
- جاهز للمتابعة / يحتاج إصلاحًا / لا يمكن اعتماد التعديل بعد.
